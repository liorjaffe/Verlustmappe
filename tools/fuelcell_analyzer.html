% of baseline
Mark at least one region around a transient event (e.g. FC start-up, a load step) in the Time Series tab first.

About this analysis

Reuses the regions you marked in the Time Series tab. For each region:

Baseline = average of the last few points just before the region starts.
Extreme = the point inside the region furthest from baseline (the dip/spike itself).
Fall/Rise time = 10%–90% transition time from baseline to the extreme.
Recovery time = time after the extreme until the signal first returns within the tolerance band around baseline. Shows "did not recover" if it never does within the marked region — extend the region if so.

Times are shown in seconds. If your file's time column isn't a real timestamp (e.g. a plain elapsed-time column), that column's own unit is assumed to be seconds.

About this analysis

Electrical efficiency = electrical power out ÷ H₂ energy in, using the H₂ flow channel converted to power via its LHV or HHV energy content. Specific consumption = NL H₂ per kWh electrical produced. Totals are computed per marked region if you have any, otherwise over the whole file.

% of peak value
Needs a Current (or Power) channel. Cycles are detected automatically wherever the signal rises above the threshold and falls back below it.

About this analysis

Cycles are auto-detected from the Current channel (or Power, if no Current channel exists): a cycle runs from the first sample above the threshold to the last one before it drops back below it. For each cycle: Start-up time is the 10–90% rise time from the pre-cycle baseline to the cycle's peak. Shutdown time is how long it takes to fall back within tolerance of the post-cycle baseline after the peak.

% of rated, between samples
Needs a Power channel (or Voltage+Current) and a rated power value above.

About this analysis

Bins are time-weighted shares of the file's duration, not sample counts. Load factor = average load ÷ peak load. Capacity factor = average load ÷ rated power. A "load change" counts each time consecutive samples differ by more than the threshold (% of rated power).

Detected anomalies (sudden changes)

About this analysis

CV% = std dev ÷ |mean| × 100. Steady-state uses a rolling std-dev window; a point counts as steady once its local variability drops to a small fraction of the channel's overall std dev. Anomalies are consecutive-sample jumps larger than the threshold × the channel's overall std dev of point-to-point changes — lower the threshold to catch more/smaller events.

Spread over time

About this analysis

Spread = max cell voltage − min cell voltage at each moment. The bar chart shows each cell's average voltage across the whole file, sorted by cell number, so a consistently weak cell stands out. "Worst cell" is the one with the lowest average voltage.

About this analysis

Voltage at a fixed current is the standard, load-independent way to track fuel-cell degradation across sessions with different load profiles (same approach DOE/NREL evaluations use). Degradation rate is the linear-regression slope of V vs. operating hours, shown in mV/h and %/h relative to the first session.

Pick a dataset and channel, then click Analyze. Uses a rolling median/MAD (robust z-score) instead of mean/std, so a few large outliers don't skew the detection itself.

Detected events

Steady segments (event-free, ≥ min steady)

About this analysis

Deviation score = |value − rolling median| ÷ rolling MAD (median absolute deviation, scaled) — a robust alternative to mean/std that isn't itself thrown off by the outliers it's trying to find. An event is a run where the score exceeds the threshold, merged with nearby runs and filtered by minimum duration. Plateau = median of the window just before the event. Recovery = time until the signal returns within tolerance of the plateau and stays there for the hold duration (not just a single touch). Steady segments are everything left over once events are removed, above the minimum duration — the usable data for comparisons.
